# 企业微信智能机器人接入说明

## 一、与现有企业微信通道的区别

项目里有两套企业微信能力，**不能混用**：

| 能力 | 自建应用 `app/channels/wecom.py` | 智能机器人 `app/channels/wecom_bot.py` |
|---|---|---|
| 产品形态 | 自建应用 | 智能机器人（API 模式） |
| 凭证 | CorpID + Secret + AgentId | BotID + Secret |
| 接收消息 | 公网 HTTPS 回调 + 消息加解密 | WebSocket 长连接，无需加解密 |
| 发送消息 | `message/send` 主动下发 | 流式回复 / 模板卡片 |
| 适用 | 按 userid 推送、接收应用消息 | 用户与机器人对话 |

`WECHAT_WEBHOOK_URL` 是群机器人**单向通知**，与上述两者都不同。

## 二、企业微信后台准备

1. 登录企业微信管理后台 → 应用管理 → 智能机器人。
2. 创建一个 **API 模式**机器人。
3. 记录 `BotID` 与 `Secret`。
4. 在机器人「可使用权限」中按需授权。

## 三、本地配置

在 `.env` 中填写：

```env
WECOM_BOT_ENABLED=true
WECOM_BOT_ID=你的BotID
WECOM_BOT_SECRET=你的Secret
# 逗号分隔的成员 userid；留空 = 拒绝所有人（安全默认）
WECOM_BOT_ALLOWED_USER_IDS=zhangsan
```

`WECOM_BOT_ID` 与 `WECOM_BOT_SECRET` 缺失时，程序会**拒绝启动**，不会建立任何连接。

## 四、运行

```powershell
pip install -e .
python -m app.channels.wecom_bot
```

预期日志：

```text
企业微信智能机器人长连接启动中（bot_id=xxxxxxxx）
企业微信智能机器人长连接鉴权成功
```

## 五、当前实现范围

实现范围：

- WebSocket 长连接建立、鉴权、心跳与自动重连
- 文本消息接收（单聊 / 群聊 @机器人）及群聊前缀处理
- userid 白名单校验，留空时拒绝所有用户
- 寒暄/帮助类短消息欢迎语
- 非文本消息能力提示
- `PolicyAgent` 与 `ConversationService` 接入，按渠道、会话和用户隔离上下文
- Agent 调用线程池隔离与失败日志
- 流式回复（`finish=false` → `finish=true`）

仍需真实环境确认或尚未覆盖：

- 企业微信真实租户的端到端消息验收
- 图片、语音、文件的内容解析；当前仅提示改用文字
- 长任务回执与明确的用户侧超时提示
- 与现有 `BaseChannel` 抽象完全统一
- 生产级高可用；同一机器人只能保持一个有效长连接

## 六、已知限制（来自企业微信官方文档）

1. **同一机器人只能保持一个有效长连接**：新连接会踢掉旧连接。
   因此只能单实例运行，高可用需主备切换。
2. **单用户最多 3 条消息并发交互中**。
3. **流式回复最长 6 分钟**，超时后结束推送。
4. **群聊消息需 @机器人** 才会触发回调。
5. 若机器人创建者不是企业超级管理员，`from.userid` 为加密 userid，
   白名单需填加密后的值。

## 七、人工验收清单

配置租户、BotID、Secret 和白名单后，启动长连接并逐项验证：

- [ ] 单聊文本提问能收到流式回复。
- [ ] 群聊中 @机器人 能触发回复，普通群消息不会误触发。
- [ ] 不在白名单的用户会被拒绝。
- [ ] 寒暄或帮助短消息返回欢迎语，不进入政策检索。
- [ ] 同一会话内可完成多轮上下文追问。
- [ ] 图片、语音或文件消息收到明确的文字能力提示。
- [ ] 断线后能自动重连，且日志不泄露 Secret、完整 userid 或消息正文。
- [ ] Agent 超时或异常时用户收到可理解的提示，服务继续接受后续消息。

测试时应使用授权测试账号和脱敏样例，不要使用真实企业成员敏感信息。
